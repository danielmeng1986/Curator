# UI-028 — Enforce Workflow Interruption Readiness

## Task ID

`UI-028` — Status: `Ready`

## Title

Add Specification-Level Interruption Coverage to the UI Readiness Gate

## Related Specification(s)

- [UI Specification](../Specification.md), sections 7 and 8.
- [Workflow Readiness Matrix](../Workflow-Readiness-Matrix.md).

## Goal

Make the final gate prove each workflow's applicable interruption and recovery
contract instead of accepting only an uninterrupted happy path.

## Scope

- Machine-readable per-workflow applicability for modal close, route change,
  refresh, browser restart, Backend restart, delayed action, retry,
  cancellation, and client upgrade/cache behavior.
- Required browser suite ownership and reporting for each applicable boundary.
- Honest readiness classification when evidence is absent or failing.

## Workflow Contract

- Entry and preconditions: final readiness runner loads the approved workflow/interruption manifest.
- States and next actions: each boundary is applicable-and-passing, explicitly not applicable with reason, or failing/not implemented.
- Persistence and recovery: sanitized failure evidence identifies the workflow and interruption boundary; subsequent suites remain independently runnable for audit.
- Completion evidence: summary reports functional and interruption coverage separately.
- Failure safety: no live data or credentials enter fixtures/artifacts; missing evidence cannot be reported as Ready.

## Out of Scope

- Duplicating Backend business-rule regression in Playwright.
- Requiring every interruption type for workflows where it is genuinely inapplicable.

## Dependencies

- UI-023 restores disclosure gate semantics.
- UI-024–027 provide missing workflow behavior and focused tests.

## Implementation Steps

1. Extend the readiness manifest with the Specification interruption dimensions and rationale.
2. Add or register focused browser scenarios at the lowest useful layer.
3. Continue audit execution after a failure while preserving a non-zero final result.
4. Update readiness classifications from evidence generated by the manifest.

## Acceptance Criteria

- Every material workflow declares all Specification interruption dimensions.
- A missing applicable scenario fails readiness and names the owning task.
- One failed suite does not prevent the audit report from showing later suite results.
- Two consecutive clean runs remain required for final Ready classification.
- Results and artifacts remain sanitized and use disposable resources.

## Verification

- Runner contract tests, intentional missing/failing scenario fixtures, and two clean complete readiness runs.
- Documentation matrix consistency check.

## Risks or Notes

- Applicability exemptions require a concrete reason; they must not become a
  generic mechanism for skipping difficult recovery behavior.
